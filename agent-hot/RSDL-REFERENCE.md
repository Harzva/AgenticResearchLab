# RSDL 公开站点拆解与 AgentHot 对照

2026-11-20 通过公开 HTTP 和匿名浏览器核对。RSDL 的核心是两条阅读路径。首页帮助读者发现刚收录的论文，论文栏目把公众号已写过的解读按研究方向和会议期刊重新组织。AgentHot 可以把每天一个研究问题放在首位，再让论文知识库承担长期检索和原文定位。 [RSDL 首页](https://rsdl.info/) · [公众号论文分享](https://rsdl.info/papers)

## 更新、互动与技术证据

- **更新日期有不同口径。** 本次首页开头四条显示 `收录 2026-11-20`，紧接着可见 arXiv 的 `2026-11-19`。页脚显示「最近同步 2026/11/20 20:00:19」，界面未标注时区。论文栏另有公众号卡片日期。这些公开样本支持「当天新增可见」，采集频率、刊发时刻和排序规则仍需要历史记录才能确定。AgentHot 应分别保存源发布日期、收录时间和专题发布日期，经典案例在当期仍显示最初的公开日期。 [最新研究](https://rsdl.info/) · [论文栏目](https://rsdl.info/papers)
- **栏目与方向可以交叉。** 论文页有内容分类、方向及刊会筛选，社区页也能按方向浏览。一些征稿标题同时出现在论文和社区页。AgentHot 可用一个稳定工作 ID 在多个专题和研究方向回指同一原文，用 DOI、arXiv 主版本号、官方论文主页和作者仓库合并重复条目。 [论文](https://rsdl.info/papers) · [社区](https://rsdl.info/community)
- **互动与订阅的证据各有范围。** 首页能看到收藏按钮与反馈表单，邮箱验证码用于登录。关于页提供联系邮箱和研究社群微信入口，站点另有投稿路径。此次只读观察了入口。匿名浏览的多个页面没有发现 RSS 的 `rel=alternate`，公开常见地址 `/rss.xml` 和 `/feed.xml` 实测为 404，邮件定时订阅也未在所查公开页面发现。 [首页和反馈](https://rsdl.info/) · [关于与联系方式](https://rsdl.info/about) · [投稿](https://rsdl.info/contribute)
- **网页公开证据能确定的技术范围。** HTML 引用 `/_next/static/chunks/app/` 模块，可确认 Next.js 公开前端。HTTP `Server` 响应头声明 Apache。初始 HTML 有加载提示和空计数，正常浏览器填充首页与论文列表，因此抓取 HTML 时的 `0` 只是初始状态。首页页脚明确把 arXiv 和 Crossref 列为元数据来源，并说明自动分类用于检索。后台调度、数据库、清洗细节和账号实现属于未观察信息。 [首页及其公开 HTML](https://rsdl.info/) · [论文页](https://rsdl.info/papers)
- **旧入口的迁移教训。** 搜索索引仍可见曾按「会议再年份」「期刊名」「跨栏目方向」组织的旧 `/portal/` 页面。实测 `www` 首页现跳转到主域名，旧期刊、赏读和智能体路径在本次 HTTP 请求中返回 404。AgentHot 的历史专题应保留日期页和稳定条目 URL，发布首页时保住已分享的链接。 [现行首页](https://rsdl.info/) · [现行论文分类](https://rsdl.info/papers)

## AgentHot 每日专题怎么做

1. **每天选一个可回答的研究问题。** 首期沿着找文献、提假设、跑实验、做迭代组织 12 条。后续围绕一个主题做一组条目，保留已经核对的经典案例。可依次做「怎么核对论文引用」「怎么设计可证伪的 Agent 评测」「一个实验怎样算复现成功」「怎样衡量 Agent 自我改进」。 [RSDL 的方向与自动发现入口](https://rsdl.info/)
2. **把来源核对做成发布前的检查。** 优先读官方会议论文、arXiv 作者稿、作者或机构报告、官方实现。每项写清对象、实验设置和数字口径，再给一个能验证的动作。预印本升为刊会版本时更新同一条目，版本和来源保留。证据不足的当天可发布档案专题，并标出各源的真实日期。 [RSDL 论文与资源的入口设计](https://rsdl.info/papers) · [模型资源实例](https://rsdl.info/models)
3. **让读者追更，让 Agent 拿到可复查的材料。** 维护当期与历史专题入口、RSS、JSON、`llms.txt` 和条目 Markdown。首页 RSS 可直接订阅，文章内保留来源、PDF 和正式解读链接。内容纠错先收清楚是哪页、哪一条和可以核对的来源，核实后更新原条目并记录修订。 [RSDL 的反馈与联系入口](https://rsdl.info/about)
4. **用一次发布回执控制多端节奏。** 每天只生成一个专题 ID，先校验来源及页面再更新首页与订阅索引。面向公众号、X 和哔哩哔哩的文章或视频使用已审核的专题材料，各平台记录独立的正式回执。把「已收录」「已审」「已发布」分别显示。 [RSDL 公众号论文分享](https://rsdl.info/papers) · [公开投稿入口](https://rsdl.info/contribute)
